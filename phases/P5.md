# P5 — Content blending

**Goal:** the five signature moments. Build in order; stop when it feels right. Each one must degrade to a static, readable state.
**Read:** `SPEC.md` §3, §5, §6.
**Exit:** smoke tests for plunge, sonar ping, dive line, torch, ascent.

## P5.1 BuoyChip

**Files:** `components/ui/BuoyChip.tsx`, `lib/signal.ts`.
"Available for work" chip pinned to 30% of `--vh`. `--bob = -T.bobPx × (0.7·sin(x·6 + t·1.5) + 0.3·sin(x·17 − t·2.3))` px, where `x = chipCenter / innerWidth` — the same two frequencies the shader uses at `wl`, scaled to `T.bobPx` (8 px). Written on the chip element only; `transform: translateY(var(--bob))`. Hidden under reduced motion and on coarse pointers.
**Done:** the chip tracks the waterline while scrolling; no layout shift (it is `position: absolute`).

## P5.2 ProjectCard motion

**Files:** `components/ui/ProjectCard.tsx`.
`hover` **and** `focus-within` show a CSS ping ring and, when present, the `Architecture` chain. Thumbnail desaturation, if any, is static CSS — never a per-frame var. No JS animation.
**Done:** a keyboard user gets the same information as a mouse user; no `setState`.

## P5.3 Skills torch

**Files:** `components/sections/Skills.tsx`, `lib/signal.ts`.
Runs **inside the main loop** — no second `rAF`. Cache each `[data-skill]` page-relative centre on mount and on resize; per frame compute viewport y as `pageY - scrollY` and write `--glow` (0–1) on that node only, when it changed. Off for reduced motion and coarse pointers.
**Done:** moving the pointer lights nearby skills; the loop count stays 1 (assert by counting `requestAnimationFrame` calls in a test hook).

## P5.4 DiveLine

**Files:** `components/ui/DiveLine.tsx`.
Fixed right: thin rule, metres readout, zone label. One passive scroll listener writing through refs; `setState` only when the zone id changes. `aria-hidden="true"` plus a `sr-only` live region that announces the zone at most once per change.
**Done:** the readout tracks scroll; the DOM updates at most once per zone change.

## P5.5 Case-study dive and ascent

**Files:** `components/casestudy/CaseStudy.tsx`, `components/ui/BackToSurface.tsx`, `components/sections/Contact.tsx`.
Case-study zones come from `lib/layout.ts` + `data-zone` — no GSAP, no ScrollTrigger, no second scroll system. Contact lantern: one warm radial glow, `#ff9f43` (the only warm colour on the site). Keep it small and dim — C2 asserts the last viewport's mean blue exceeds mean red, so a dominant warm glow would break the constraint. `BackToSurface` → `scrollTo({ top: 0, behavior: reduced ? 'auto' : 'smooth' })`.
**Done:** the case study visibly dives and rises; the ascent is instant under reduced motion.
